## 1. 결정 사항

### 1.1 범위
| 항목 | 결정 |
|---|---|
| 이번 작업 | 화면(A) + 목업 API를 상대로 한 데이터 연결(B). 전환·배포(B8)는 제외 |
| 기준 동작 | 현행 기능 + 새 API가 바꾼 동작. 새 API 기능 중 아래를 포함 |
| 학생 기능 추가 | 투표 요청·취소, 홈 4개 목록, 회원 탈퇴, 모든 기기 로그아웃 |
| 관리자 기능 추가 | 투표 관리(회차 개설·마감 변경·종료·재개설·cutoff, 회차 생성) + 요청 큐, 통계 숨김·이동, 로그 내보내기(5형식)·필터 삭제·전체 비우기·보관 이력, 계정·운영 콘솔(관리자 부여·회수, 계정 조회, 대시보드, 카탈로그, 잡) |

### 1.2 기술
| 항목 | 결정 |
|---|---|
| 프레임워크 | React Router 8 framework 모드(SSR). RSC(`unstable_*`) 미사용 |
| 언어·런타임 | TypeScript, Node 24, pnpm |
| 위치 | `web/` |
| 스타일 | `public/styles.css`를 CSS Modules로 분할. Tailwind 미사용. 어두운 테마 유지 |
| 린트·테스트 | ESLint + Prettier, Vitest + Testing Library, Playwright |
| CI | 나중에(백엔드와 함께) |
| API 호출 | 모두 React Router 서버(loader/action) 경유. 브라우저가 `/api/v1`에 직접 가는 것은 OAuth, 관리자 파일 미리보기, 로그 내보내기 다운로드뿐(같은 출처 프록시) |
| API 클라이언트 | `openapi-fetch` + `openapi-typescript` 생성 타입 |
| 계약 파일 | `web/api/openapi.yaml` = `feature/go-backend` 워크트리의 `docs/api/openapi.yaml`을 가리키는 **미커밋 심볼릭 링크**. 생성 타입(`web/app/api/schema.d.ts`)은 커밋 |
| 목업 | `web/mock-api/` (Hono). 웹 코드는 import하지 않고 HTTP 주소로만 연결. 빌드에 포함하지 않음 |
| 목업 데이터 | 원본 학기 JSON 9개에서 카탈로그 생성, 기여 데이터(통계·투표·한줄평 등)는 예시로 작성 |
| 계약 검증 | 목업의 모든 응답을 OpenAPI 전용 검증 라이브러리로 검사하는 테스트. 링크가 없으면 건너뜀 |
| 개발 로그인 | 환경변수(`DEV_LOGIN=1`)가 켜졌을 때만 로그인 화면에 이메일 입력 폼. 프로덕션에서 켜면 기동 실패 |

### 1.3 화면·동작
| 항목 | 결정 |
|---|---|
| 라우팅 | 주소 라우팅. 검색창은 레이아웃에 두어 강의를 바꿔도 유지 |
| 검색 | 검색어를 주소에(`?q=`), 서버가 첫 페이지 렌더링. 20개씩 무한 스크롤(JS 없으면 "더 보기" 링크) |
| 홈 목록 | 검색어가 없으면 왼쪽 검색창에 즐겨찾기·투표 진행중·최근 제보·요청 많은 강의 |
| 강의 상세 | 기존 섹션 순서 유지: 난이도 투표(회차 선택) → 통계량(회차 열 포함, 모든 회차) → 제보 → 한줄 후기 |
| 기본 회차 | 투표가 열린 회차 중 최신. 없으면 현재 학기 + 날짜 기준 시험 형태, 그것도 없으면 최신 회차 |
| 날짜 기준 시험 형태 | 서울 시간, 서버 계산 |
| 마지막 강의 | 쿠키(30일)에 저장, 새로 들어올 때 `/`에서 서버가 리다이렉트. 상단 'Archive' 링크를 누르면 쿠키를 지우고 빈 검색 화면 |
| 폼 | 가능한 곳은 JS 없이도 제출(`<Form>` + action). 임시저장·글자 수·숫자 키 차단은 JS 로드 후 덧붙임 |
| 접기·펼치기 | 제보 카드, 모바일 검색창은 `<details>` |
| 결과 메시지 | action이 서버 flash 쿠키에 담고 다음 화면에서 토스트(JS 있으면 2.6초 후 사라짐) |
| 위험 작업 | 탈퇴, 로그 비우기·필터 삭제, 관리자 회수는 확인 페이지를 거쳐 실행 |
| 계정 | `/me` 페이지: 프로필 수정, 모든 기기 로그아웃, 탈퇴. 프로필 배너는 기존처럼 유지 |
| 관리자 메뉴 | 묶음 + 하위 탭(2절) |
| 오류 화면 | 한국어 |
| 상단 메뉴 | 관리자에게만 Admin 표시(`/me.isAdmin`) |
| 파비콘 | 없음 |
| 브라우저 저장 키 | 현행 `snu-archive:*` 키를 바탕으로 새 API 형식(강의 id)에 맞춰 수정 |

### 1.4 현행 결함 처리
- 학기 표시 반전 → `/config.semesters` 라벨 사용으로 해결
- 시험 형태 선택지 불일치 → `/config.assessmentKinds`(종류 × 번호)로 해결
- 관리자 로그 로드 실패 → 오류로 표시
- 남은 투표권 표시 → 새 API에 투표 한도가 없어 해당 없음

### 1.5 작업 방식
- A~B를 끊지 않고 진행, 단계마다 검사(타입·린트·포맷·Vitest·E2E) 통과 후 커밋. 끝에 한 번 보고
- push는 요청할 때만
- 예상 못 한 결정은 **먼저 5절에 기록한 뒤** 건너뛰고, 끝에 모아서 질문
- 화면 비교: 기존 사이트(로컬 데모 로그인 + 같은 예시 데이터)와 새 화면의 스크린샷 쌍을 저장소 밖에 남김

### 5.1 보류 — 결정 필요

| # | 항목 | 현재 처리 |
|---|---|---|
| P1 | 홈 "즐겨찾기" 목록은 API가 최대 10개만 준다. 기존에는 즐겨찾기 전부가 목록 맨 앞에 나왔다. 전체 즐겨찾기(`/me/favorites`)로 가는 링크나 화면을 둘지 | 10개만 표시, 링크 없음 |
| P2 | 모든 API 호출이 React Router 서버를 거치므로 Go가 기록하는 활동 로그 `ip`·`users.last_ip`가 프론트 서버 주소가 된다. `X-Forwarded-For` 전달·신뢰 방식을 백엔드와 정해야 함 | 전달하지 않음 |
| P3 | 계약의 `AdminPendingReport.fileUrl`이 무엇에 대한 상대 경로인지 불명확(`/api/v1/...`인지 API 기준 경로인지) | 둘 다 처리 |
| P4 | 휴대폰 폭(≤734px)에서 기존 화면은 상단 이메일을 숨겼다. 그러면 `/me`로 가는 길이 없어서 짧은 "계정" 링크를 임시로 넣음 | 임시 처리 |
| P5 | 관리자 "통계 옮기기"와 "회차 만들기"는 대상 강의를 **강의 ID 숫자**로 받는다. 강의 검색으로 고르게 할지 | 강의 ID 입력 |
| P6 | 관리자 폼의 연도 선택지 범위(현재 기준 6년 전 ~ 내년). 계약에 기준이 없다 | 6년 전 ~ 내년 |

### 5.2 정한 사항 — 검토용

- 강의 상세 섹션 순서는 기존 CSS 동작을 따른다: 투표가 열린 회차가 있으면 투표 → 통계 → 제보, 없으면 통계 → 제보 → 투표. 그다음 한줄 후기, 관리자 섹션.
- 프로필 배너 "나중에"는 기존 sessionStorage 대신 브라우저 세션 쿠키(`web_profile_banner`, 이메일 값)에 둔다. 서버가 배너를 그리지 않을 수 있고 JS 없이도 동작한다.
- 직접 제보 임시저장은 기존 키(`snu-archive:direct-report-draft`)를 그대로 쓰고 값의 `courseKey`를 새 API의 `courseId`로 바꾼다. 기존 형식의 임시저장은 강의를 특정할 수 없어 무시한다. 닉네임 키(`snu-archive:last-nickname`)는 그대로.
- `/config`에 개발 로그인 여부가 없어 프론트 환경변수 `DEV_LOGIN=1`로 켠다(1.2절 결정대로).
- 한줄 후기 작성자가 탈퇴해 `author`가 null이면 "(탈퇴한 사용자)"로 표시.
- 한줄 후기 삭제는 기존처럼 강의 페이지에 두지 않고 관리자 "검토 > 한줄평"에서만 한다.
- 새 기능 문구(기존에 없던 것): 홈 "요청 많은 강의"의 "요청 N건" 배지, 투표 섹션의 "시험" 선택·"투표 요청"·"요청 취소"·메모 입력, "{시험} 난이도"(회차별 집계라 기존의 "누적" 제거), 토스트 "투표를 요청했습니다."·"투표 요청을 취소했습니다."·"프로필을 저장했습니다."·"모든 기기에서 로그아웃했습니다."·"탈퇴했습니다.".
- 오류 문구는 계약 방침대로 오류 코드별로 프론트가 정하고(`app/lib/errors.ts`), 없는 코드는 서버 `message`를 쓴다.
- 검색 결과 순서는 서버가 정한다(강의명 접두 일치 → 최근 개설 → 강의명). 기존의 즐겨찾기·투표중 우선 정렬은 홈 목록이 대신한다.
- JS가 있을 때만 적용되는 규칙(빈 폼 제출 버튼 비활성, 글자 수 초과 비활성, 번호 칸 숨김)은 `<html class="js">`와 hydration 여부로 켠다. JS가 없으면 서버가 검증한다.
- 한줄 후기·검색의 "더 보기"는 JS가 없으면 다음 페이지만 보여 주는 링크(`?comments=`, `?cursor=`)로 동작한다.
- 관리자 "검토 > 제보"는 기존처럼 모든 상태(대기·승인·반려)를 10개씩 보여 준다. 대기 건만 승인·반려 폼이 있다.
- 관리자 로그 시각은 기존처럼 날짜만 보이고, 마우스를 올리면 전체 시각이 나온다.
- 관리자 로그 "비우기" 확인 화면에 이주 전 주의 문구(백엔드 open-items O2)를 한 줄 넣었다.
- 대시보드의 최근 N일 추이는 차트 없이 합계와 날짜별 표(접어 둠)로 보여 준다.
- 관리자 마감·기준 시각 입력(`datetime-local`)은 서울 시간으로 읽고 쓴다.
- 새 관리자 기능의 배치(묶음 탭 아래 하위 탭, 확인 페이지)는 기존 관리자 화면의 스타일(카드, 수정 그리드, "더 보기")을 따른다.
